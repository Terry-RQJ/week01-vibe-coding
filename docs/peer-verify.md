## 一、给同伴的操作说明（照做即可）

### 你要打开的两个链接

1. **首页**：https://rqj-2006-d0gl1ael531a243a1-1497985433.tcloudbaseapp.com/
2. **检查台**：https://rqj-2006-d0gl1ael531a243a1-1497985433.tcloudbaseapp.com/check.html

> ⚠️ **首次打开会跳出腾讯云「页面访问提示」**——这是腾讯云测试域名的统一行为，不是网站故障。
> 等按钮上的倒计时（约 3 秒）走完 → 点「**确定访问**」。有时会有**两层**提示，再点一次即可。

### 步骤 1：能否打开（2 分钟）

1. 打开首页 → **6 张卡片**应该都能看到标题和一句话摘要
2. 点任意一张卡 → 能进详情页，能看到**法条原文**（不是一片空白）
3. 首页搜索框输入「**押金**」→ 应该有 **1 条**结果
4. 打开检查台 → 页面应显示三个板块：**健康状态 / 核心表数据 / 写入测试**

### 步骤 2：能否真实读写（3 分钟，最关键）

5. 在检查台找到「**写入测试**」板块
6. 点「**测试收藏**」按钮 → 应返回成功，并显示一个**时间**
7. **再点一次**同一个按钮 → 应提示「**已经收藏过了**」（这是对的，说明防重复生效）
8. **刷新整个页面（F5）** → 刚才那条收藏**应该还在**
9. 点「**取消收藏**」→ 应提示已取消；**再刷新** → 列表应为空

> 判断要点：第 6 步和第 8 步之间**刷新过浏览器**，东西还在 → 说明是**存到服务器**了，不是存在浏览器里。

### 步骤 3：有无报错（1 分钟）

10. 按 **F12** 打开开发者工具 → 切到 **Console** 面板
11. 刷新页面 → 看有没有**红色**的错误信息
12. 切到 **Network** 面板 → 刷新 → 点头部带 `api` 的请求 → 看请求地址是不是以 `…ap-shanghai.app.tcloudbase.com` 开头

## 四、如果同伴验证不通过怎么办（预案）

| 症状 | 最可能原因 | 我的处置 |
|---|---|---|
| 打开白屏 / 一直转圈 | 停在腾讯云「页面访问提示」没点确定 | 让 TA 再点一次「确定访问」（可能有第二层） |
| 页面能开但卡片区空 | 网络拦截了 `*.tcloudbase.com`（公司网关/校园网常见） | 换手机 4G 热点重试 |
| Console 报 `Failed to fetch` | 同上，或跨域被中间代理改写 | 让 TA 提供 F12 报错原文，我记录到下周 |
| 点收藏一直转圈 | 接口超时（写入链路慢） | 记下时间点，检查云函数日志 |
| 刷新后收藏没了 | **真问题**，说明没写进库 | 立即记录为 FAIL，查 `favorites` 表与云函数日志 |

> 注：**除了最后一条，其余都不是代码缺陷**，是测试域名中间页和网络环境的正常现象。同伴验证时要注意区分「打不开」和「环境限制」。

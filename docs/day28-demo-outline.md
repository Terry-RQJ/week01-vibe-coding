## 第一段｜用户问题（约 40 秒）

**要解决的问题**：普通人遇到法律麻烦，第一反应是搜法规原文——看不懂；找律师——成本高、也没到那一步。

**这个站做什么**：把「发生在我身上的事」做成一张**情形卡**——大白话讲清楚「发生了什么、第一步做什么、依据哪条法」，法条带官方原文链接。不替代律师，只解决「我该不该慌、下一步干嘛」。

**一句话定位**：不是法律百科，是**遇事第一步**。

**28 天证明了什么**：一个只学了一个月编程的人，能交付一个**真数据库 + 公网接口 + 上线可访问**的全栈小站，而不是一个本地 HTML 演示。

## 第二段｜核心流程（约 2 分钟，全部现场真实操作）

### ① 真实数据（30 秒）

- 打开公网地址 → 6 张情形卡（劳动 / 消费 / 借贷 / 婚姻家庭 / 邻里 / 交通）
- **F12 → Network**：指着请求说「这些都打到 `…ap-shanghai.app.tcloudbase.com/api/...`——数据真的存在腾讯云的 PostgreSQL 里，经云函数读出来，不是写死在前端的假数据」
- 点开「公司劝退我，该怎么办？」→ 详情页三区块 + 3 条法条 + 「原文出处 ↗」跳国家法律法规数据库

### ② 搜索与筛选（20 秒）

- 搜索「押金」→ 命中 1 条（说明检索走数据库 SQL，不是前端数组过滤）
- 点「劳动类」筛选 → 只剩 1 张卡，再点恢复

### ③ 收藏 → 刷新持久化 → 取消（40 秒，本段核心）

1. 点某张卡右下角 **☆** → 按钮变「★ 已收藏」+ toast
2. **按 F5 刷新** → 仍是「已收藏」（数据存浏览器 localStorage，刷新不丢）
3. 顶部「我的收藏」→ 该卡在列；点 ☆ 取消 → **卡片立刻消失**（不刷新）
4. 回首页 → 该卡已回到「☆ 收藏」——四页状态一致

### ④ 写入数据库（40 秒）

- 打开检查台 `/check.html` → 「写入测试」选一张卡 → 点「收藏」
- 结果区显示 **HTTP 200** + 写入时间；紧接着 **GET 读回**该列表，证明**写入真的落库**了
- 重复点一次 → **409**「这张卡片已经收藏过了，请勿重复提交」；点「取消」→ removed=1；再点 → removed=0（幂等）

### ⑤ 验收证据收尾（20 秒）

- 打开 `day28-shot-acceptance-checklist.png`（或 docs/day28-acceptance.md）：10 项 PASS 逐条有当天证据，3 项「未执行」如实标注
- 「回滚演练实测过：部署回滚 8~11 秒、公网恢复 20~30 秒」

## 第三段｜提示词改写（约 40 秒）

**28 天里提示词用法的变化**（挑两个真实例子讲）：

| 阶段 | 一开始的写法 | 后来改成的写法 | 为什么改 |
|---|---|---|---|
| Day 8–14 | 「帮我做一个收藏功能」 | 「收藏存 localStorage（key=LAW_BOOKMARKS），加 toast 反馈，失败回滚按钮状态，按钮要有 busy 态防连点」 | 模糊指令得到的代码没法验收；**把验收标准写进提示词**，产出才能直接用 |
| Day 24（修 Bug） | 「收藏接口有 Bug 帮我修一下」 | 固定模板三段式：**现象（一句话客观表现）+ 复现步骤（设备/URL/点了什么/预期 vs 实际）+ 已尝试动作（换设备/看控制台/刷新各是什么结果）** | 补齐三段后 AI 一次命中；缺任何一段，AI 就开始猜 |

**一句话总结**：提示词从「说需求」进化成「给证据 + 定边界 + 写验收标准」——这也是 Day 24 修复模板沿用至今的原因。

## 第五段｜平台限制（约 30 秒，如实说）

1. **环境 2027-03-30 到期**（体验版）——不续费则站点与接口一并下线，这是最大的单点风险
2. **免费版中间页**：首次访问弹腾讯云「页面访问提示」，要点一次才能进——演示和试用都要过这关
3. **网关不支持 RESTful 子路径**：`DELETE /api/favorites/:slug` 改成了 `?id=` 形态（契约里写明了原因）
4. **网关层英文报错**：未编码的中文参数会被网关以英文 `Bad Request` 挡回（浏览器正常路径不受影响，P2 记账）
5. 无真人试用：Day 27 由记录人自跑替代，效力低于真人

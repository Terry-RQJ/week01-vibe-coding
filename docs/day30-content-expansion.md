### 2.3 内容仍然只有一个源

改内容仍只需改 `db/seed-content.py` → 重新生成 → 导库：

```
db/seed-content.py  ──生成──▶  db/seed.sql     （tcb db execute 入库）
        │                ──生成──▶  data/cards.js  （store.js 离线回落）
        └── 写盘前自检：分类合法 / slug 唯一 / 字数上限 / 法条 1~4 条 / tags ≥4 / related 存在
```

`tags` 这次被当成**口语别名**用：普通人说「押金」「扰民」「退钱」，法条写的是「租赁合同」「噪声」「返还」，
所以每张卡的 tags 都强制 ≥4 个并刻意写口语说法——**搜索能不能搜到，很大程度取决于这一步**。

## 3. 法条核验：逐条对官方原文，顺带修了 3 处历史错误

**纪律**：新增卡片的每一条法条都从**官方全文**按条号抠原文，不凭记忆书写。
工具是临时的 `.tmp-extract.py`（从 12371.cn / 人大网 / 政府网 / 最高法 页面提取指定条号原文），
核验后再写进 `seed-content.py`。

过程中发现并修正了 **3 处此前就存在的错误**：

| # | 问题 | 修正 |
|---|---|---|
| 1 | 装修噪声标成《噪声污染防治法》**第 58 条** | 58 条讲的是「综合治理方案」；按关键词反查应为**第 66 条**（室内装修应限定作业时间、采取有效措施），已改正并替换原文 |
| 2 | 《道路交通安全法》第 76 条引的是 **2004 年旧版公报页** | 换成 **2021 修正版**全文（旧版与新版的赔偿规则差异很大） |
| 3 | 民间借贷司法解释出处 `gongbao.court.gov.cn` 页 **302 自环无限重定向**（已失效） | 换成**最高法国际商事法庭** `cicc.court.gov.cn` 的 2020 年第二次修正版全文 |

另一个坑：《治安管理处罚法》**2025 年修订版 2026-01-01 施行，条号整体重排**（全法 144 条）。
按旧版猜的 42/44/49/51/59/71/76/100 条号**全部对不上**，只能按关键词反查真实条号——
侮辱诽谤恐吓偷窥骚扰 = **第 50 条**、散布谣言 = **第 29 条**、社会生活噪声 = **第 88 条**、
饲养动物 = **第 89 条**、高空抛物 = **第 43 条**。

## 4. 新增「法条速查」页（`laws.html`）

用户要的「直接给法条」，落成一个独立页面 + 独立读接口 `GET /api/laws`（契约见 `api-contract.md` §1.4）。

**关键设计：以法条为主体聚合。** 此前法条是挂在卡片下的附属数据；直接平铺会出现重复——
消保法第 24 条被 6 张卡引用，就会显示 6 个一模一样的条文块。现在按法条名 `GROUP BY` 聚合成
「**一条法条 + cards[] 回指情形**」，页面渲染成「出自情形 A、B、C」，点进去即到对应详情页。

**关键词必须扩到卡片字段。** 法条原文是法言法语，「押金」这个词在条文里根本不存在
（原文写「租赁合同」），所以 `/api/laws` 的 keyword 检索范围包含**关联卡片的标题/摘要/情境/标签**——
搜「押金」能返回 4 条法条，且每条都告诉你「出自哪张情形卡」。

页面能力：顶部搜索框（法言法语 + 口语词都能搜，命中词高亮）、法律名筛选 chip（17 部，可点击/可深链
`laws.html?law=民法典`）、官方原文外链、统计行「共收录 158 条法条原文」、断网时回落本地静态法条池。

## 5. 顺手修的两个真 Bug

### 5.1 云函数响应**逐分片解码**导致多字节汉字损坏（数据侧，影响正确性）

四个云函数 `db.js` 原来这样写：

```js
let d = "";
res.on("data", (c) => (d += c));       // ❌ 对每个 TCP 分片单独做 UTF-8 解码
```

多字节汉字的字节被 TCP 分片切开时，**每个字节会各变成一个 U+FFFD 替换符**。
症状极隐蔽：`/api/laws?law=民法典` 返回的「《民法典》第 1203 条」里「《」变成 3 个乱码，
导致这条按法律名筛不出来；**而不带筛选时（响应更长）又完全正常** —— 极易误判成数据库里数据坏了。

修复：收进 Buffer 数组、最后 `Buffer.concat(chunks).toString("utf8")` **一次性解码**，四个函数全部重新部署；
发布前检查新增 **C28** 专项防止回归。

### 5.2 e2e 脚本缺超时会**静默退出且退出码为 0**（工具侧，影响可信度）

`docs/day30-laws-e2e.js` 的 CDP 调用原来没有超时。页面涨到 158 条法条后，整页截图
（`captureBeyondViewport`）产出 3MB+ base64 失败、Edge 不回应 → promise 永不 resolve →
**Node 事件循环空转，进程以退出码 0 正常退出**。表现是「测试跑一半就停了、没有报错、退出码还是 0」，
比直接报错更危险（很容易被当成「通过」）。

修复：每次 CDP 调用带 60s 超时；截图改只截视口且失败时降级跳过不中断整轮。

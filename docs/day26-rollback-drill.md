## 0. 演练口径

- **回滚目标**：v0.9.0 = `8081183`（Day 25，上一个稳定版）
- **被回滚版本**：v1.0.0（当天刚发布）
- **演练路径**：静态托管回退（CloudBase 默认域名，`tcb hosting deploy`）
- **判定标准**：公网 `index.html` 的 SHA-256 与 `git archive` 导出的目标版本**逐字节一致**，且版本徽标消失/出现正确
- 两轮：第 1 轮专注计时，第 2 轮为交付截图复跑（顺带验证可重复性）

## 3. 耗时结论

| 指标 | 实测 |
|---|---|
| 回滚部署动作 | **8 ~ 11 秒** |
| 回滚 → 公网恢复可用（含 CDN 生效） | **约 20 ~ 30 秒** |
| 完整演练（回滚→验证→恢复→再验证，不含留证） | **约 1 分钟** |
| 两轮耗时波动 | ±3 秒内，**可重复、不靠运气** |

> 注：CDN 生效的 9~18 秒是**缓存自然过期**，不是操作耗时；真正的人工动作只有一条命令。真出事时，从「发现异常」到「公网恢复」的瓶颈在**判断要不要回滚**（判断表见 `rollback-playbook.md` §1），不在技术执行。

## 4. 「真出事敢不敢用？」——敢，理由三条

1. **步骤少**：静态托管回退 = 导出 + 一条 `tcb hosting deploy` 命令 + 一条 curl 验证，没有隐藏步骤，演练跑过两轮都是同一条路
2. **有保险**：`--safe` 在覆盖前自动备份当前线上版本——就算回滚错了，也能再退回来；第一天发布还真实触发过一次自动回滚，机制被验证有效
3. **可验证**：不靠"看起来恢复了"，靠 SHA-256 指纹逐字节比对 + 版本徽标可视化确认，退没退对一眼可辨

风险与边界（诚实记录）：
- 本演练只覆盖**静态托管**；云函数回退路径写了但没实操过（今日边界），真用到时按 `rollback-playbook.md` §4 走，第一次最好留出排错时间
- 数据风险极小：用户收藏只存浏览器本地，服务端内容表可从仓库重建——这是纯前端架构带来的天然优势
- CDN 缓存是最不可控的一环（分钟级），验证必须带 `Cache-Control: no-cache`，且"出现旧特征"和"消失新特征"两个方向都要查

## 5. 卡点记录（真实踩到）

| 卡点 | 症状 | 处理 |
|---|---|---|
| `--verify` 一致性校验失败 | 发布 11 秒后报 `missing=.nojekyll`，自动回滚 | `.nojekyll` 是 GitHub Pages 专用文件，CLI 不上传；加 `--ignore .nojekyll`。已写进发布清单 |
| CloudBase 免费版中间页 | 浏览器访问弹「页面访问提示」，curl 不弹；按钮要求**可信点击**，JS `.click()` 点不动 | 用 CDP `Input.dispatchMouseEvent` 派发真实鼠标事件（等倒计时走完再点） |
| 抓屏抓到桌面壁纸 | 两次抓屏之间 Edge 掉到后台，`ImageGrab` 抓屏幕矩形就成了别的东西；改 `PrintWindow` 又抓到黑图（Chromium 硬件加速） | 最终：地址栏用窗口抓屏（每次抓前 `AttachThreadInput` 强制前台）+ 整页用 CDP `captureBeyondViewport`（不依赖滚动与焦点） |
| tcb CLI 再次丢失 | 环境重置后 `tcb` 命令没了（Day 21 已发生过一次） | 重装 `@cloudbase/cli` 到隔离目录；登录态在 `~/.config/.cloudbase`，仍有效无需重登 |

## 第一段｜用户问题（约 40 秒）

**要解决的问题**：普通人遇到法律麻烦时，第一反应是搜法规原文，但看不懂；找律师问，成本高。

**这个站做什么**：把「发生在我身上的事」变成一张**情形卡**——用大白话讲清楚「这意味着什么」「第一步做什么」「依据哪条法」。不替代律师，只解决「我该不该慌、下一步干嘛」。

**一句话定位**：不是法律百科，是**遇事第一步**。

**本周要证明的事**：内容不是硬编码在前端的假数据，而是**真的存在数据库里、通过公网接口读出来的**——这意味着以后加卡、改法条，不用改代码、不用重新部署。

## 第二段｜核心流程（约 2 分钟，含一次真实写入 + 刷新持久化）

### ① 打开首页，看真实数据（30 秒）

- 地址栏：`…tcloudbaseapp.com`
- 页面：**6 张情形卡**（劳动 / 消费 / 借贷 / 婚姻家庭 / 邻里 / 交通）
- **切到 F12 → Network**：指着请求说「这些都是 `…ap-shanghai.app.tcloudbase.com/api/...` 的**公网地址**，不是本地 mock 文件」
- 点任意一张卡进详情 → 看到**法条原文**（3 条），说明「卡和法条是两张表，通过外键关联，一次请求取回来」

### ② 搜索与筛选（20 秒）

- 搜索框输入「**押金**」→ 命中 1 条（房东不退押金）
- 演示「内容检索走的是数据库 SQL，不是前端 JS 数组过滤」

### ③ **真实写入 + 刷新持久化**（40 秒，本段核心）

**这一步是最关键的证据，务必完整走：**

1. 打开公网**检查台** `…/check.html` → 滚到「写入测试」板块
2. 点「**测试收藏**」→ 页面返回 **200**，显示 `favorited_at` 时间戳
3. **再点一次**同按钮 → 返回 **409**「这张卡片已经收藏过了」→ 证明**数据库层防重复**（不是前端拦的）
4. **按 F5 刷新整个页面** → 检查台自动重新 `GET /api/favorites` 读回 → **刚才那条收藏还在** → **这就是持久化**
5. 点「**取消收藏**」→ 返回 `removed: 1` → 再刷新 → 列表空 → 证明取消也是真写库

> 讲法：「如果收藏只存在浏览器里，换个浏览器就没了。现在它存在 PostgreSQL 里——刷新、换设备、发给别人，都在。」

### ④ 改数据 → 刷新跟着变（30 秒，可选，时间紧可跳过）

- 现场在控制台把某张卡的标题加个「（演示）」→ 回首页刷新 → 标题变了 → 立刻改回
- 讲法：「内容和代码是分开的，改数据不用重新部署。」

## 第三段｜提示词改写过程（约 50 秒）

**本周最花时间的一步，也是提示词迭代最密的一段。**

| 轮次 | 我的原始提示词（大意） | 出来的问题 | 我怎么改写 |
|---|---|---|---|
| 1 | 「写接口访问数据库」 | 用了 Node 18 才有的全局 `fetch`，本地跑通、**部署后直接挂**（线上是 Node 16.13） | 补上约束：「运行环境是 Node 16，不能用全局 fetch，必须用 https.request」 |
| 2 | 「跨域加上允许头」 | 函数自己设了 `Access-Control-Allow-Origin: *`，网关又拼一次 → 变成 `origin,*` 双值，浏览器拒收 | 改成**反向约束**：「不要自己设 CORS 头，交给网关按 Origin 回；并给出用 curl 带 Origin 验证的方法」 |
| 3 | 「加一个详情接口 /api/cards/:slug」 | 网关把子路径**归一化**成列表路由，详情永远取不到 | 改成「详情改用查询参数 `?slug=`」——**并让 AI 同步更新契约文档**，避免文档和实现对不上 |
| 4 | 「写收藏接口」 | 重复提交能写进去两条 | 改成两层要求：「① 表级 `UNIQUE(client_id, card_slug)` 兜底 ② 业务层捕获 23505 转 409 **中文**报错」 |
| 5 | 「重构代码」 | 差点把 SQL 拆到跨目录共享，但 CloudBase **按函数目录独立打包**，require 不到 | 补上环境约束：「CloudBase 每个函数单独打包，共享代码要按函数目录各放一份」 |

**我这周学到的提示词方法（三句话）**：
1. **把运行环境的坑写进提示词**（Node 版本、打包方式、网关行为）——不写，AI 就会按通用最佳实践给你一个上不了线的漂亮方案。
2. **要求可验证，而不是要求正确**——「给出用 curl 怎么验」比「保证正确」有用得多。
3. **改了接口就同步改契约**——让 AI 一起改文档，不然三天后自己都忘了为什么用 `?slug=`。

## 第四段｜验证方式（约 40 秒）

**不是「我看着没问题」，是三层证据：**

1. **接口层（21 项回归）**——重构前后各跑一遍同样的 21 个请求，响应体**逐字节对比**（只归一化时间戳字段）→ 完全一致。项目 `DEPLOY.md` §14。
2. **数据层（真实读回）**——写入后立刻 `GET` 读回，条数对得上；取消后读回为空。刚才演示的就是这个。
3. **穿透验证（改库跟着变）**——在数据库控制台改一个标题，刷新页面看到变化，再改回来。证明数据真的是从库里来的，不是接口里写死的。
4. **周验收表**——`docs/week3-acceptance.md`，33 项逐项给结论（29 PASS / 0 FAIL / 4 未执行），每项附可复现命令。
5. **同伴交叉验证**——`docs/peer-verify.md`，请同学按三行结论独立验证一遍。

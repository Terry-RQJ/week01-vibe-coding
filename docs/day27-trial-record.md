## 1. 六步走查结果（修复前）

| 步 | 客观判据 | 结果 |
|---|---|---|
| 1 公网可达 | 首屏出现「最新情形」卡片 ≥ 1 | ✅ |
| 2 详情可读 | 详情页有「发生了什么 / 第一步该做什么 / 相关法条」三区块 | ✅ |
| 3 核心操作 | 点 ☆ 后按钮变「★ 已收藏」+ toast | ✅（但见卡点 #2：按钮不在「右下角」） |
| 4 刷新持久 | 刷新后按钮仍「★ 已收藏」 | ✅ |
| 5 状态一致 | 详情页按钮与列表页一致，可点回去 | ✅（但见卡点 #3：bfcache 场景） |
| 6 删除一致 | 收藏页点 ☆ 后卡片消失 | ❌ **卡片不消失，要点刷新**（卡点 #1） |

**第一个找不到/不理解的地方**：脚本第 3 步说「点那张卡片**右下角**的 ☆」——
在 375px 宽度下 ☆ 按钮根本不在右下角，它跟着「交通类 · 📄 · 核验 2026-09-22」
这行字排下来，落在**左下角**（证据：`day27-mob-03-bookmarked.png`，修前截图）。
一个第一次用的人会先盯着卡片右下角找，找不到才往左扫。这不是试用者的错，
是**页面提示文案、试用脚本、按钮实际位置三者不一致**。

## 3. 修复内容与验证

### #1 收藏页取消后立即移出列表
- `js/page-bookmarks.js`：新增 `onFavToggled` 回调——取消成功后把该卡片从 DOM 移除、计数减一；清空时切「还没有收藏内容」空态。
- `js/ui.js`：`onFavClick` 支持页面传入 `opts.onToggle` 回调（页面各自决定取消后做什么，渲染层不写死）。
- 验证：线上实测点 ☆ 后 **1135ms 内卡片消失（不刷新）**，计数行同步变「已收藏 1 个情形」；两张全取消后正确切空态。截图 `day27fix-empty-state.png`。

### #2 ☆ 按钮固定到卡片右下角
- `css/global.css`：`.card .card-meta .fav-btn { margin-left: auto; }`，按钮推到 meta 行最右端。
- 验证：线上实测按钮右缘 x=334 vs 卡片内容区右缘 x=335（**差 1px**），是 meta 行最右元素；修前距右缘 >100px。截图 `day27fix-btn-position.png`。

### #3 bfcache 返回后状态同步
- `js/ui.js`：新增 `UI.syncFavButtons(root)` + 全局 `pageshow`（`e.persisted`）时按 Store 当前值刷新所有收藏按钮。
- `js/page-bookmarks.js`、`js/page-history.js`：内容完全由 localStorage 派生的两页，bfcache 恢复时直接整页重渲染（新收藏/新浏览记录也能出现）。
- 验证：把已收藏按钮的 DOM 状态手动改旧，`syncFavButtons()` 一次刷回 `is-on=true`（pageshow 走同一函数）。

### #4 attachFavHandler 幂等
- `js/ui.js`：容器加 `__favBound` 标记，重复调用只更新 opts 不再叠加监听（否则 #1 的修复路径自己就会触发双重 toggle）。

### #5 README 死链
- `README.md` 部署章节改为 CloudBase 现役地址 + 指向 DEPLOY.md / 发布清单 / 回滚手册，并明确标注 Pages 方案已废弃勿用。
